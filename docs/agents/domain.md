# Domain docs

This is a single-context repository.

Before exploring domain behavior, read the root `GLOSSARY.md` if it exists and read relevant decisions in `docs/adr/`. If neither exists, proceed without creating them preemptively. Add domain terms or architecture decision records when the corresponding domain-modeling work resolves them.

Use established glossary terms in issues, tests, and design notes. If a proposed change conflicts with an existing ADR, identify that conflict before proceeding.
